# 精算合成

- **来源**: 精算师 — 汇总所有框架输出，判断证据是否一致，输出结论 + 置信度
- **触发时机**: 所有其他框架跑完后，下单前的最后汇总
- **角色**: 综合判断。一张票经过 10 个框架，有的说"可以"，有的说"警告"——精算合成给出最终判决。

## 核心逻辑

10 个框架各自输出二元判断（通过/拒绝/警告）。精算合成不重新分析数据，而是检查：**这些判断之间是否一致？如果不一致，不一致的地方暴露了什么风险？**

## 输入
- 所有框架的输出（通过/警告/拒绝 + 理由）
- 当前市场状态
- 账户状态

## 分析步骤

### 步骤 1：汇总表决矩阵

| 框架 | 判断 | 理由摘要 |
|------|------|---------|
| 物理层 | 通过 | 均值回归服从 A 股约束 |
| 对手方 | 通过 | 对手方 = 恐慌散户，缩量确认离场 |
| 反身性 | 警告 | 当前在过热区，信号可能衰减 |
| 量化验证 | 通过 | 中位 +3.0%, 胜率 57.4%, 样本 17,250 |
| 安检门 | 通过 | 8 条全过 |
| 增量审计 | 通过 | 裸 DD30 基线，无叠加过滤器 |
| 仓位 | 通过 | 凯利 8.9%，单票 25% 内 |
| 组合相关 | 通过 | 当前持仓无同信号源重叠 |
| 尾部风险 | 警告 | 左尾 5%: -24.3%，连续 2 次扛不住 |

### 步骤 2：一致性检查

- **全部通过**: 高置信度 → 绿灯
- **1 个警告**: 中高置信度 → 绿灯但谨慎
- **2-3 个警告**: 中低置信度 → 黄灯，降仓执行
- **任何拒绝**: 不进

当前案例：2 个警告（反身性 + 尾部风险）→ 黄灯。

### 步骤 3：方向性检查

警告是同方向还是不同方向？

- 反身性警告：市场过热 → 信号可能衰减 → 收益可能低于历史中位
- 尾部风险警告：左尾宽 → 亏损可能超过预期

两个警告都是下行的。方向一致 → 警告信号更强。

### 步骤 4：置信度赋值

| 置信度 | 条件 |
|--------|------|
| 高 | 全部通过 + 样本 > 1000 + 前向验证稳定 |
| 中 | 1-2 个警告 或 样本 200-1000 |
| 低 | 3 个警告 或 样本 100-200 |
| 不进 | 任何框架拒绝 |

## 输出
```
最终判断: 黄灯 — 降仓执行
置信度: 中
风险点: [反身性] 当前过热区信号可能衰减; [尾部] 左尾-24.3%单笔风险大
建议: 仓位从 8.9% 降至 5%，硬止损设在 -15%
```

## 与交易员铁律的关系
精算合成说"可以，但有风险"。交易员铁律说"有风险的部分你实际能不能执行"。两者独立——精算师不代替交易员的判断。

## 反例
- 如果 10 个框架 9 个说通过、1 个说拒绝——精算合成仍然输出"不进"。一个致命缺陷不能被 9 个通过票覆盖。
