# 尾部风险

- **来源**: Taleb — 分布能告诉你很多，但不能告诉你黑天鹅。尾部风险框架处理"分布没说的事"
- **触发时机**: 仓位确认后，下单前
- **角色**: 找出历史分布覆盖不到的最坏情况 → 设置硬止损 → 确保你能活过黑天鹅

## 核心逻辑

Layer 0 给你的分布是基于历史的。但历史没有覆盖的事：
- T+1 下连续跌停无法卖出
- 政策突变的系统性冲击
- 流动性枯竭（涨跌停封死）

尾部风险框架不预测这些。它只做一件事：**用硬规则限制单次最大损失**。

## 输入
- Layer 0 左尾统计
- 账户规模
- 票的流动性特征（日均成交量、是否 ST、是否有跌停历史）

## 分析步骤

### 步骤 1：历史左尾检查

| 分位 | 值 | 含义 |
|------|-----|------|
| 左尾 5% | -24.3% | 20 次里有 1 次亏这么多 |
| 左尾 1% | -40%+ | 100 次里有 1 次亏这么多 |

在 ¥40K 账户上：
- 左尾 5%: -24.3% → ¥9,720
- 左尾 1%: -40% → ¥16,000

### 步骤 2：连续极端情景

历史最坏情况 × 连续发生：

```
连续 2 次左尾 5%: ¥40K → ¥30K → ¥22K (亏 45%)
连续 3 次左尾 5%: ¥40K → ¥30K → ¥22K → ¥17K (亏 58%)
```

如果连续 3 次后账户还剩不到 50% → 仓位太高。需要降。

### 步骤 3：流动性尾部风险

检查票是否可能无法卖出：
- ST 股票 → 禁止
- 日均成交额 < ¥5M → 流动性不足 → 禁止
- 近 30 天有连续 2 天跌停 → 标记高风险

### 步骤 4：硬止损规则

无条件执行，不因"我觉得会反弹"而修改：

```
单日回撤 > 5%:  无条件减半仓
单笔亏损 > 15%: 无条件清仓
单月回撤 > 10%: 暂停交易 1 周
单季回撤 > 20%: 暂停交易 1 月 + 全面复盘
```

### 步骤 5：黑天鹅准备金

总资产的 20% 不在任何交易中（总仓位上限 80% 已保障）。这 20% 不追求收益，只用于：
- 黑天鹅后补仓
- 保证金追加
- 心理缓冲（知道有备金 → 不容易恐慌卖出）

## 输出
- **正常**: 左尾可接受 + 流动性充足 → 下单
- **警告**: 左尾偏大但可接受 → 减仓 + 设硬止损
- **拒绝**: 流动性不足 或 连续极端情景 < 50% → 不下单

## 关键约束
- 硬止损规则不可被任何其他框架覆盖。安检门过了、量化验证过了——如果硬止损触发了，必须执行。
- Bootstrap 鲁棒性通过 ≠ 尾部安全。Bootstrap 说分布估计稳定，不是说极端事件不会发生。

## 反例
- DeepDD30 左尾 5% 分位 -24.3%。Bootstrap VaR 置信区间宽度只有 0.58%，分布估计稳定。但 − 这不能保证下一次触发不会亏 30%+。黑天鹅不服从历史分布。
