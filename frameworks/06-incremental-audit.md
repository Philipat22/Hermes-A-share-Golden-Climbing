# 增量审计

- **来源**: OpenClaw 外部审计 — 任何新想法必须证明它比裸基线"好多少"，并判断"好了多少才值得"
- **触发时机**: 有人提出"加一个过滤器会更好"或"叠加一个条件"时
- **角色**: 量化验证 + 安检门通过后，新过滤器上线前的最后一道防线

## 核心逻辑

**数据的默认假设是：每加一个过滤器，期望收益降低。直到被数据证明不是。**

不是"加了试试看"。是"先证明加了更好，才加"。

## 输入
- 裸基线分布（如：裸 DeepDD30，无过滤器）
- 新过滤器分布（如：DeepDD30 + PE<20）

## 分析步骤

### 步骤 1：计算增量

| 指标 | 基线 | 新过滤器 | 增量 | 结论 |
|------|------|---------|------|------|
| 中位 | +3.0% | +3.8% | +0.74pp | |
| 胜率 | 57.4% | 58.1% | +0.7pp | |
| 样本量 | 17,250 | 8,640 | -50% | ⚠️ |

### 步骤 2：判断增量是否有意义

阈值：
- 中位增量 > 2pp？→ 有意义的改善
- 中位增量 1-2pp？→ 边际改善，需权衡样本损失
- 中位增量 < 1pp？→ 噪音 — 拒绝
- 样本量损失 > 30%？→ 过滤器过强 → 拒绝

PE 案例：中位增量 +0.74pp < 1pp → 噪音。拒绝。

### 步骤 3：检查副作用
- 样本量损失超过中位增量收益？
- 是否引入了新的尾部风险？
- 是否和现有过滤器高度相关（冗余）？

### 步骤 4：逐过滤器验证
如果同时提出 3 个过滤器（如：PE + 量缩 + 板块），必须逐个验证，不能打包。

```
DeepDD30 基线:           中位 +3.0%
DeepDD30 + PE:           中位 +3.8%  → 增量 +0.74pp → 噪音 → 拒绝
DeepDD30 + 量缩:         中位 +1.3%  → 增量 -1.7pp → 降效 → 拒绝
DeepDD30 + 板块(热门):   中位 +5.0%  → 增量 +2.0pp → 通过 → 保留
```

打包验证 = 你把一个有效的和一个降效的混在一起，平均值看不错，但上了实盘会亏钱。

## 输出
- **增量 > 2pp + 样本损失 < 30%**: 通过，过滤器加入
- **增量在噪音范围**: 拒绝
- **降效**: 拒绝 + 记录为"已验证无效，不要再提"

## 与量化验证的关系
量化验证告诉你"信号有没有效"。
增量审计告诉你"加了东西后有没有变得更好"。
两个是不同的检验。量化验证通过 ≠ 增量有意义。

## 反例
- PE 过滤器：中位增量 +0.74pp → 增量审计拒绝 → 不在 Layer 1 中加 PE
- 量缩过滤器：中位从 +3.0% 降到 +1.3% → 降效 → 增量审计拒绝 → 不在 Layer 1 中加
- 如果当时没有增量审计，PE 和量缩可能已经被写进 Layer 1 代码，然后实盘跑赢的历史中位会掉 1.7pp
